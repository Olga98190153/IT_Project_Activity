# Иерархическая структура работ
1. Определение требований (requirements): назначение, функции, ограничения.
2. Проектирование (design): состав интерфейса, модель узлов и потоков, форматы файлов.
3. Разработка (development): интерфейс, модель, редактор, экспорт.
4. Тестирование (testing): проверки модели, импорта и экспорта, ручные проверки интерфейса.
5. Документирование (documentation): руководство, подготовка к публикации.
6. Основная ветка (main): объединение завершённых изменений.

## Категории участников
Владелец репозитория управляет настройками, доступом и объединением изменений. Разработчик вносит изменения через ветки при предоставлении прав записи. Проверяющий просматривает содержимое публичного репозитория; для изменения файлов нужны отдельные права. Это план распределения доступа, а не утверждение о добавленных участниках.
